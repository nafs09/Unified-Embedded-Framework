# Security policy

## Supported releases

The project is pre-release and does not yet promise security maintenance for
released versions. Before a release policy is announced, report issues
affecting the default branch or the latest published release, if any.

## Reporting a vulnerability

Do not publish suspected vulnerabilities, exploit details, credentials, or
weaponizable proof-of-concept code in a public issue, pull request, or
discussion. Use GitHub's **Report a vulnerability** action for this repository
when private vulnerability reporting is enabled. If it is unavailable, use the
security contact listed in the repository's GitHub **About** section.

Include the affected component and version/commit, target and configuration,
impact, reproduction steps, and any known mitigation. Redact keys, secrets,
personal information, and unrelated device logs. Maintainers will coordinate a
response and disclosure; there is no response-time guarantee during this
pre-release period.

Before making the repository public, maintainers must enable GitHub private
vulnerability reporting and verify that the fallback security contact is
monitored. The `SECURITY.md` file alone does not enable private reporting.
