# UPROTO communication protocols

UPROTO provides portable protocol-facing APIs for embedded links and message exchange.

## Contents

- <code>uproto.h</code> is the module umbrella. `rc/` groups CRSF, DShot, PPM and SBUS; `can/` groups CANopen and UAVCAN; `network/` groups Bluetooth, WiFi and IP services. MAVLink, framing and USB device contracts remain at the layer root.
- <code>CONNECTIVITY.md</code> documents the active WiFi, Bluetooth, and IP provider contracts and the first-pass TLS/DTLS, MQTT and HTTP outlines. PPP, CoAP and Thread/Zigbee remain later outlines. External modules use UPAL transports; integrated chips bind target SDK providers.
- `industrial/` groups Modbus, shared industrial contracts, IEC 60870 and LIN. `can/` contains first-pass CANopen CC, with separate CANopen FD (CiA 1301/USDO) in `can/future/`. All these outlines remain generation-blocked.
- `can/future/` also contains the independent [Myovena MEDI CAN protocol scaffold](can/future/medi_can.h), extending CANopen FD with planned acknowledged delivery, integrity/freshness, recovery and execution gating. See the [MEDI CAN design](../../docs/design/can/MEDI_CAN.md).
- Other planned outlines live in `rc/future/` (ELRS and MSP), `can/future/` (J1939 and UAVCAN v1), and `network/future/` (PPP, CoAP and mesh). IEC 60870 and LIN retain their later status within `industrial/`.
- These future modules remain non-generatable until their provider, external-stack identity, target integration, and qualification evidence are selected. They do not represent UETD-owned full protocol stacks.
